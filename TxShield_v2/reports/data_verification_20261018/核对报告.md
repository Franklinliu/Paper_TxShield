# 四份实验数据核对报告

核对范围：pic/file/data 下四份 CSV、readme，以及 pic/file 下三个 detailed_results 文件。只读核对，没有修改原始数据或论文。CSV 模型指标按值为 0/1 的有效预测计算；其余值单独记为无效，不擅自转成正常或攻击。

## 文件含义

1. history_knowledge.csv：209 行、209 个唯一 hash。字段为 contract_name、hash、year_month、matched_date、attack_type。它是历史事件元数据/攻击类别目录，不包含行为摘要、执行轨迹、向量或检索索引，单独该文件不能证明运行时具体检索了什么。
2. 用户说明中的 defiattack_original_multimodel_728.csv 在目录中不存在；实际文件是 defiattack_original_noxgboost_728.csv。含 728 行，七列预测，包括 GPT-4.1-mini(noRAG)。各模型有效预测数不同；不包含 Kimi_k3、Deepseek-v4-pro、GPT-5.6-luna 的无 XGBoost 对应列，因此不能直接用它与新三模型作前后配对比较。是否未使用 XGBoost 依据文件说明，单独预测 CSV 无法证明执行路径。
3. defiattack_with_xgboost_728.csv：728 行，四个模型。Kimi 和 Deepseek 完整；GPT 有一条 -1；Qwen 有 140 条非二元预测，仅 588 条有效，按用户说明仅供参考。
4. ablation_study_kimi_k3.csv：728 行，predicated_label 与另两份的真实标签完全相同，因此在本文件中应作为 ground truth 理解，名字容易引起误解。三列分别为 norag、test_abl_no_two_stage、wo_xgboost；无完整系统列，完整系统需从 with 文件的 Kimi_k3 获取。列名和 CSV 无法确认 no_two_stage 是否同时关闭 XGBoost，也不能确认 norag 是否保留 XGBoost。当前论文将 no_two_stage 写成同时移除两者，这一点需要运行配置佐证。

三份评估文件均为 728 个唯一 hash，交易集合完全一致，标签均为 364 攻击、364 正常，逐交易标签差异为 0。

## 详细 JSON 的新线索

按文件名 hash 对齐（正常样本文件名补齐 0x 前缀）：Kimi 728 条预测和标签全部与 CSV 一致；Deepseek 也是如此；GPT 仅一条预测不一致，标签均一致。

- GPT 差异 hash：0x3d5c15fe152403f42c4840145c92b04fc863ba8b35828419f91773c956480fe。真实标签正常，CSV=-1；JSON predicted_label=Attack，回答也以 Attack 开头。不能不经确认就覆盖任一来源。
- Deepseek hash：0x11c1ef2c61f5a2e41d570a1547d2d891bf916853ddd94e32097e86bcdd21cb4c。JSON 的 answer_content 以 Benign 开头，但 predicted_label=Attack，CSV 也为 1。需要核对解析/汇总流程及该条原始 response，不能仅凭最终列认定纯后过滤。
- 按 ML/XGBoost/classifier/machine-learning 关键词检索，Kimi 259 条、Deepseek 162 条、GPT 3 条回答包含相关文字。此计数只用于定位，不代表全部都是实际模型概率输入。
- 明确例子：Kimi 第一条攻击回答末尾为“ML 0.989 concurs.”；GPT 的 0xb650e9f4b9eb023ea65b55ca4d088323e3d5bda377880dedb149a7fd3fd5c15f 回答称“XGBoost probability (0.994) supports classification.”；Deepseek 的 GPT 差异 hash 回答明确提及 XGBoost 概率 0.847。

这些文字与“XGBoost 只在 LLM 输出后执行，概率不进入提示词”的当前实现不一致，提示历史运行可能有不同的数据流。但也可能涉及输出加工或模型自行生成文字，未见当时提示词和代码，不能确认具体机制。JSON 中没有成对的 llm_prediction/final_prediction/xgb_applied/threshold 字段，无法重建完整过滤过程。
