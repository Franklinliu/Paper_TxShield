# TxShield 新增实验与结果整理报告

日期：2026 年 9 月 16 日  
主题：LLM 与 XGBoost 组合检测、组件消融，以及直接 XGBoost 分类对比

## 1. 主要结论

在当前提供的 728 条测试记录上，三种新 LLM 骨干与 XGBoost 组合后的 F1 分别为 **89.45%（GPT-5.6-luna）、91.16%（DeepSeek-v4-pro）和 92.93%（Kimi-k3）**，均高于直接 XGBoost 分类的 **86.48%**。其中，Kimi 组合的精确率最高，达到 **97.87%**，误报由直接 XGBoost 的 60 条降至 7 条；DeepSeek 组合的召回率最高，达到 **89.29%**，检测到 325 条攻击。[S1–S4]

现有结果支持“LLM 与数值特征分类器的组合有助于改善检测结果，尤其是减少误报”的观察。**新骨干的组合结果不能直接当作 XGBoost 单独贡献的消融证据**：新旧实验同时更换了 LLM，而新骨干缺少同配置、不启用 XGBoost 的逐条结果。论文中的 GPT-4.1-mini 消融表提供了组件收益的初步证据，但部分数值与现有 CSV 不一致，需统一实验版本。[S5–S6]

本报告区分“逐条数据重算结果”“论文已有汇总”和“尚待核实的实验设置”。当前数值可用于内部分析；在作为论文最终结果前，应优先核实知识库与测试集标识交叉、XGBoost 的实际介入位置，以及计时口径。下文保留所有这些限制，不据此推断已经发生训练泄漏或宣布某种架构已被严格验证。

### 2.2 方法描述及版本差异

按本次任务说明，新增方法的定位是：**TxShield 的 LLM 方法输出初步结果后，使用 XGBoost 进一步过滤**。若实际实现是只对攻击候选执行否决，可将最终决策写为：

`最终攻击 = LLM 判为攻击 且 XGBoost 分数达到阈值 τ`。

这一公式只是对“硬否决式后处理”的条件化定义，不能替代实现核验。飞书报告的现有描述是：RAG 触发后才启用 XGBoost；低分否决 RAG，高分作为参考值传给大模型。因此，飞书描述更接近“检索触发的门控与概率辅助推理”。部分 JSON 中的 LLM 回答也引用了 ML 概率，例如 Kimi 第一条记录提到 0.989，说明至少部分推理过程可见该分数。最终论文应以对应结果的实际代码版本为准，区分以下三种机制：[S1–S3、S7]

- **LLM 输出后硬过滤**：直接修改候选攻击标签。
- **LLM 推理前的检索门控**：修改是否使用检索证据。
- **概率辅助推理**：向 LLM 提供 XGBoost 分数，由 LLM 作出最终判断。

这一区分影响结果解释。若组合与直接分类使用完全相同的 XGBoost 模型、阈值和输入，且对全部样本实施严格 AND 规则，则组合的 TP 不可能超过 XGBoost-only 的 TP。但当前 DeepSeek 组合 TP=325，高于 XGBoost-only 的 323。该现象提示两者可能存在门控、阈值、模型或数据版本差异，不能在未核对时同时声称“完全相同分类器”和“严格全量 AND 后处理”。

### 2.3 数据集与数据处理

新旧两份多模型 CSV 均含 737 个解析数据行，其中 **728 行具有 0/1 标签，另有 9 行无标签尾部记录**。本报告仅保留带标签的 728 行。新旧表的样本标识集合和真实标签一致，均为攻击 364 条、良性 364 条。三份 JSON 各有 728 条记录，统一文件名中的 `0x` 前缀后，其标识集合与 CSV 一致，预期标签也一致。[S1–S3、S5]

攻击为正类：TP 是正确识别的攻击，FP 是良性误报，TN 是正确识别的良性，FN 是攻击漏报。使用以下标准二分类指标：

- `Accuracy = (TP + TN) / N`
- `Precision = TP / (TP + FP)`
- `Recall = TP / (TP + FN)`
- `F1 = 2TP / (2TP + FP + FN)`
- `FPR = FP / (FP + TN)`

文中“提升 x 个百分点”指比例的绝对差乘以 100；“误报减少 x%”指 FP 数量相对于对照的减少比例。`NULL` 和 `-1` 不擅自改写为良性或攻击，单独报告预测覆盖率。

`result.csv` 有 573 条记录，并非 728 条二分类测试集；`history_knowledge.csv` 有 209 条记录，均包含在该 573 条列表中。因此，不能把 `result.csv` 全表直接作为本次测试集计算二分类指标，也不能把它的 `predicted_label` 当作真值。知识库文件与测试集的交叉详见第 7 节。[S8–S9]

### 2.4 XGBoost 的特征与训练

飞书展示的特征提取代码包含 14 项候选特征：调用数、事件数、最大调用深度、不同合约数、transfer/approve/flashloan/delegatecall/selfdestruct 标志、高金额标志、总 value、最大 value、不同函数签名数、未知签名数。它们主要反映调用复杂度与交易数值特征。飞书还提到删除零贡献特征，因此最终训练实际使用的特征列表需与模型文件核对。[S7]

代码中的金额项来自调用节点的 `value`，不能未经验证就解释为已统一代币精度、法币价格或完整 ERC-20 转账的“总资金流”。飞书有关金额特征贡献较大的结论目前属于原报告说明，本目录没有可复核的特征重要性数值。

直接分类的训练结果明确区分了训练集 420 条（210 攻击、210 良性）与测试集 728 条（364 攻击、364 良性）。调参结果如下：[S4、S7]

| 参数 | 最佳值 |
| --- | --- |
| max_depth | 3 |
| learning_rate | 0.02 |
| min_child_weight | 1 |
| subsample | 0.9 |
| colsample_bytree | 0.7 |
| reg_alpha | 0 |
| reg_lambda | 0.5 |

报告中的最佳交叉验证 F1 为 0.9374，早停后验证集 AUC 为 0.9569；训练全集 F1 为 0.9421，测试集 F1 为 0.8648，测试 AUC 为 0.9467。交叉验证/训练指标不能替代测试指标。现有整理材料尚未把交叉验证折数、验证集划分、随机种子、最终树数、分类阈值和训练样本标识清单与三组组合结果逐一关联，应补充这些配置以实现完整复现。

飞书“修改参数前”还给出 F1=0.9357、FP=0 的另一组 728 样本结果。由于该组与调参后结果的训练/评估关系未得到本次材料验证，本报告将其视为历史调参记录，不选择它作为最终 XGBoost-only 基线。

## 3. 主实验：与直接 XGBoost 分类比较

### 3.1 分类性能

表 1 使用三个组合模型的逐条 JSON 重算结果，以及直接 XGBoost 测试集混淆矩阵。各组标称样本均为 728 条；直接 XGBoost 未提供逐条预测，因此无法进一步验证其样本身份或执行配对显著性检验。[S1–S4]

| 方法 | TP | FP | TN | FN | Accuracy | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| XGBoost-only | 323 | 60 | 304 | 41 | 86.13% | 84.33% | 88.74% | 86.48% |
| TxShield + XGBoost，GPT-5.6-luna | 318 | 29 | 335 | 46 | 89.70% | 91.64% | 87.36% | 89.45% |
| TxShield + XGBoost，DeepSeek-v4-pro | 325 | 24 | 340 | 39 | 91.35% | 93.12% | 89.29% | 91.16% |
| TxShield + XGBoost，Kimi-k3 | 322 | 7 | 357 | 42 | **93.27%** | **97.87%** | 88.46% | **92.93%** |

模型名称沿用实验文件，不将旧表的 DeepSeek-R1 与新表的 DeepSeek-v4-pro、或 GPT-4.1-mini 与 GPT-5.6-luna 视为同一个骨干。

### 3.2 相对直接分类的收益与代价

| 组合骨干 | Accuracy 变化 | Precision 变化 | Recall 变化 | F1 变化 | FP 净减少 | FN 净变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| GPT-5.6-luna | +3.57 个百分点 | +7.31 个百分点 | −1.37 个百分点 | +2.97 个百分点 | 31（51.67%） | +5 |
| DeepSeek-v4-pro | +5.22 个百分点 | +8.79 个百分点 | +0.55 个百分点 | +4.68 个百分点 | 36（60.00%） | −2 |
| Kimi-k3 | +7.14 个百分点 | +13.54 个百分点 | −0.27 个百分点 | +6.45 个百分点 | 53（88.33%） | +1 |

**Kimi 组合表现为最强的误报控制。** 在 364 条良性样本上，其 FPR 从 XGBoost-only 的 16.48% 降至 1.92%。攻击检测数仅少 1 条，同时正确判定总数由 627 增至 679。对需要减少告警审核负担的应用，这一结果有实际意义。

**DeepSeek 组合的精确率与召回率均高于直接分类。** 它检测到 325/364 条攻击，比直接分类多 2 条，同时误报少 36 条。在本次三组组合中，其召回率最高，但 F1 仍低于 Kimi。

**GPT 组合提供较快的记录处理时间与较好的检测性能。** 其 F1 高于直接分类 2.97 个百分点，但攻击漏报净增加 5 条；不能表述为所有指标均改善。

上述误报和漏报变化均为混淆矩阵的**净差**，不是已核对的逐条纠错数量。没有 XGBoost-only 的逐条输出时，不能声称 Kimi“修正了且仅修正了某 53 条误报”，也不能将这些差值解释为过滤器的独立因果收益。

## 4. 消融实验：组件贡献及证据边界

### 4.1 论文已有的 GPT-4.1-mini 消融

下表保留当前论文的三位小数汇总，转换为百分数；尚未用对应四组逐条日志完整复现。[S6]

| 配置 | Accuracy | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: |
| 完整 TxShield | 83.8% | 83.2% | 84.6% | 83.9% |
| 去掉 XGBoost | 81.2% | 77.4% | 88.2% | 82.4% |
| 去掉 XGBoost 和两阶段检索 | 77.9% | 74.3% | 85.2% | 79.4% |
| 去掉 RAG 框架，即 Vanilla GPT-4.1-mini | 55.1% | 78.5% | 14.0% | 23.8% |

按该表，同一 GPT-4.1-mini 配置增加 XGBoost 后，精确率提高 **5.8 个百分点**，召回率降低 **3.6 个百分点**，F1 提高 **1.5 个百分点**。其作用体现为减少误报的精确率—召回率权衡；召回损失是否可接受应结合应用目标，不宜仅因 F1 提升就直接宣布可接受。

在不启用 XGBoost 的条件下，引入两阶段检索使 F1 从 79.4% 提高到 82.4%，增加 **3.0 个百分点**。它支持检索精化对最终判别有帮助。

从 Vanilla LLM 到“基础检索、无 XGBoost、无两阶段检索”的配置，F1 从 23.8% 增至 79.4%，差值为 **55.6 个百分点**。完整系统与 Vanilla 的 60.1 个百分点差距包含检索精化和 XGBoost 的共同贡献，**不应全部归因于 RAG 单一模块**。这种逐级添加组件的比较也不能单独证明组件之间存在统计意义上的协同效应。

### 4.2 旧 CSV 与论文汇总不一致

| 可核验配置 | 旧 CSV 重算 Accuracy / Precision / Recall / F1 | 论文对应汇总 |
| --- | --- | --- |
| GPT-4.1-mini(noRAG) | 55.36% / 80.00% / 14.29% / 24.24% | 55.1% / 78.5% / 14.0% / 23.8% |
| 旧表 gpt-4.1-mini 列 | 80.91% / 77.11% / 87.91% / 82.16% | 去掉 XGBoost 行为 81.2% / 77.4% / 88.2% / 82.4% |

旧表 gpt-4.1-mini 列的 TP/FP/TN/FN 为 320/95/269/44；noRAG 列为 52/13/351/312。第一组差异超出单纯百分数展示精度的影响。旧 GPT 列与论文无 XGBoost 配置的归属也没有完整运行元数据证明，因此报告不将它们强行合并。[S5–S6]

论文完整 GPT-4.1-mini 的混淆矩阵为 308/62/302/56，重算 F1=83.92%。这一旧配置还低于新增 XGBoost-only 的 86.48%。因此，更新论文时不能继续不加限定地声称旧 GPT-4.1-mini 配置优于所有基线；应围绕新结果和对应配置重新组织主结论。

### 4.3 Qwen 的反例与缺失输出

旧 Qwen 列有 108 条 `NULL`，新增 Qwen 列有 140 条 `NULL`。两组同时具有有效 0/1 预测的共同子集为 **496 条**，包括攻击 259 条、良性 237 条。[S5]

| 共同子集上的配置 | TP | FP | TN | FN | Accuracy | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧 Qwen | 217 | 48 | 189 | 42 | 81.85% | 81.89% | 83.78% | 82.82% |
| 新 Qwen + XGBoost | 225 | 89 | 148 | 34 | 75.20% | 71.66% | 86.87% | 78.53% |

在这一可配对子集上，新 Qwen 的 F1 下降 **4.29 个百分点**，FP 增加 41 条。98 条原预测为 0 的样本变为 1，其中 75 条真实为良性。它不符合“仅复用原 LLM 标签并执行攻击否决”的单向变化模式，说明需核对重新推理、提示词、门控逻辑或其他实验差异。

496 条共同子集仅用于诊断，不代表完整 728 条上的无偏估计，也不能单凭该比较认定 XGBoost 导致下降。应如实保留 Qwen 结果，避免只展示提升的骨干；在缺失原因和配置未核实前，不使用它支持“所有骨干均受益”的结论。

## 5. 效率与错误分析

### 5.1 以逐条日志为准的耗时统计

对每个 JSON 中 728 个 `processing_time_seconds` 求均值、中位数和第 95 百分位，未删除离群值。[S1–S3]

| 组合骨干 | 汇总字段均值 | 逐条重算均值 | 中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GPT-5.6-luna | 10.21 s | **10.01 s** | 8.99 s | 13.56 s | 453.68 s |
| DeepSeek-v4-pro | 45.76 s | **35.09 s** | 25.95 s | 87.73 s | 280.38 s |
| Kimi-k3 | 20.06 s | **24.73 s** | 20.17 s | 56.62 s | 123.87 s |

三份文件的汇总均值均不能由所附逐条时间完全复现。Kimi 汇总最大值为 57.46 s，而逐条记录最大值为 123.87 s，属于明确不一致；GPT 汇总最小值 5.18 s 与逐条最小值 5.43 s 也不同。主文建议采用逐条重算口径，并保留核验说明。

GPT 在三组新骨干中具有最低的平均处理时间和 P95，但存在 453.68 s 的长尾样本。这些日志尚不能分离预处理、检索、XGBoost、LLM、网络及重试的耗时，也没有直接 XGBoost 的计时，因而不能据此量化过滤器额外开销、在线吞吐量或端到端实时保障。新实验也未提供可核验的 token 与费用统计。

### 5.2 共同漏报

三种新组合共同漏报 **22 条攻击**。按 `result.csv` 的合约名称关联，包含 TeamFinance 的 5 条流动性迁移攻击，以及 Levyathan、Umbrella、LocalTrader 各 2 条；还涉及预言机定价、奖励计算和访问控制等样本。[S1–S3、S8]

这些记录说明，较高总体 F1 并未消除复杂业务语义的检测困难。但仅凭共同漏报，无法判断责任在 LLM、输入剪枝、检索缺失还是 XGBoost 否决。后续应保存同一条交易的原始/剪枝轨迹、检索结果、LLM 原始标签、XGBoost 概率及最终标签，才能定位故障环节。

## 6. 对论文实验章节的整理建议

建议将新增结果按四个研究问题组织：

1. **RQ1：整体检测效果。** 增加 XGBoost-only 基线，以表 1 比较三种新骨干组合；保持其他已有检测器的测试覆盖范围说明。
2. **RQ2：组件消融。** 固定一个主骨干，报告完整系统、无 XGBoost、无检索精化及无 RAG；把不同骨干更换造成的收益移出消融归因。
3. **RQ3：骨干敏感性。** 对比三个完整骨干，并单独报告 Qwen 的覆盖率与异常结果。主骨干如选 Kimi，应同步更新方法、摘要、结论和成本说明。
4. **RQ4：效率。** 采用统一计时口径报告均值、中位数及 P95，并补上 XGBoost-only 和过滤器自身开销。

可用于内部讨论或论文修订草稿的结果表述如下，正式投稿前仍应解决第 7 节的实验协议问题：

> 在包含 364 条攻击交易和 364 条良性交易的当前测试记录上，直接使用 XGBoost 分类获得 86.48% 的 F1。结合 TxShield 的 LLM 推理与 XGBoost 后，GPT-5.6-luna、DeepSeek-v4-pro 和 Kimi-k3 配置分别获得 89.45%、91.16% 和 92.93% 的 F1。Kimi 配置将误报从 60 条降至 7 条，同时将召回率维持在 88.46%；DeepSeek 配置取得三种组合中最高的召回率 89.29%。这些结果表明，组合系统在本次评估中优于直接数值特征分类，优势主要体现为更高的精确率。固定 GPT-4.1-mini 的既有消融汇总也显示，增加 XGBoost 后精确率提高 5.8 个百分点、F1 提高 1.5 个百分点，但伴随 3.6 个百分点的召回率损失。新骨干仍需同配置的无 XGBoost 对照，才能进一步分离骨干升级与过滤模块各自的贡献。

## 7. 数据核验结果与正式使用前需统一的事项

### 7.1 知识库与测试集的标识交叉

`history_knowledge.csv` 的 209 个标识与测试集存在 **34 个相同标识**：其中 5 个在测试集为攻击，29 个在测试集为良性。5 个攻击交叉分别关联 GFOX、Dexible、EFVault、BarleyFinance 和 DeezNutz404。完整清单见同目录 `knowledge_test_overlap.csv`。[S5、S9]

这是**文件清单层面的交叉证据**，不能直接认定模型训练泄漏。29 个标为良性的同名记录，也可能来自对攻击输入进行修改后沿用文件名。需要用链标识、真实交易哈希、输入内容及数据生成方式核实身份，并说明良性样本究竟是原生链上交易还是合成/修改样本。

若该知识库清单确实对应测试时加载的库，5 个攻击交叉便与论文“知识库攻击与评估攻击不重叠”的陈述不一致。需提供运行时检索排除记录或重新划分后重测，而不是仅在报告中宣称已经解决。XGBoost 的训练样本清单未提供，不能从 RAG 清单直接推断 XGBoost 训练集是否泄漏。

此外，728 个测试标识中有 **27 个不满足 `0x` 加 64 位十六进制字符的长度要求**：24 个长度为 65，3 个长度为 64（均含前缀）。本次只用其原有字符串作一致性匹配，未自动补零或修改，需核实这些字段是实际交易哈希还是内部样本标识。
