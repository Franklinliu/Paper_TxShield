# 论文后续核查清单：具体查什么、用什么材料、核对后怎么处理

更新日期：2026-10-19。
本清单用于联系实验执行者和核对原始实验记录，不是新增实验要求，也不代表以下项目已发现错误。优先检查已有材料；只有已有材料无法回答且影响主要结论时，再决定是否补实验。

按作者要求，批注60（公开仓库更新）不列入此次待办。原始批注仍保留。以下10组任务覆盖其余20条待核查批注；同一问题的多条批注合并处理。

## 1. 检索时究竟使用哪些参数与分数？
对应批注：25、26、28、33。涉及方法中的 Knowledge Retrieval、实验设置及检索消融解释。

### 要查的东西
- [ ] 找到产生论文主结果的运行版本，而不只查看目前目录中的最新脚本。记录该次运行的配置、启动参数和结果文件对应关系。
- [ ] 实际 top-k 是3还是5？是否由配置传入，还是函数调用写死？不同模型和消融运行是否相同？
- [ ] 向量库返回的是L2距离、平方L2距离、余弦距离，还是已经转换的相似度？查集合创建时的距离设置及所用库版本。
- [ ] 文档向量和查询向量是否都归一化？是在嵌入接口、客户端代码还是向量库内部执行？
- [ ] 阈值作用于哪个分数，条件是“小于等于”还是“大于等于”？从检索返回到筛选之间是否执行过 `1 - distance` 或其他转换？
- [ ] 实际阈值是否来自CONFIG、默认值、命令行或外部文件？明确最终生效值。
- [ ] k和阈值如何选定？有无候选值、评估指标、调参样本及记录？如果只做经验尝试，就按实际过程说明，不称为系统敏感性实验。
- [ ] 筛选顺序是否为先top-k再阈值？最大返回数量是多少？阈值筛选后是否补足被删除的案例？

### 需要的材料
实际运行脚本、配置/启动命令、向量库集合设置、依赖版本、若干查询的原始分数和最终保留案例、已有参数尝试记录。

### 已有线索与判断方式
当前论文写 k=5、相似度阈值0.85；已提供脚本的检索调用为 k=3，CONFIG阈值为0.15，按返回分数≤阈值保留。这只是两份材料的差异，尚不能说明哪份对应主结果。
不能因为0.15+0.85=1就认定等价；必须确认实际分数定义和转换。向量归一化也不自动保证 `1-L2` 在0到1之间。
对同一排序和相同k上限，先阈值后top-k不一定产生更多有效案例；需结合是否补足、近似检索和后端查询方式判断批注33。

### 核查后应交付
一张实际生效参数表（参数、值、来源、对应实验），加一条真实查询的筛选示例。再统一论文公式、阈值、k和文字，不先改数据。

## 2. 去重和剪枝是否删除关键攻击行为？压缩了多少？
对应批注：22、23。涉及轨迹最小化算法及效率论述。

### 要查的东西
- [ ] “相同调用”的判定字段是否包括调用类型、地址、函数、参数、value和返回值？实际代码是否与算法一致？
- [ ] 去重范围是整个交易树、同一父节点下，还是同一路径？同一签名但不同执行位置是否被合并？
- [ ] 删除重复节点时是否删除整棵子树？是否保留重复次数、顺序、深度、事件或状态变化？
- [ ] 从现有数据挑选重入、循环清算、多跳交换等包含重复调用的实例，对照压缩前后轨迹，检查决定攻击性质的行为是否仍可见。
- [ ] 最大深度截断、字符串截断和静态查询删除各自的配置是什么？是否在所有实验中一致？
- [ ] 是否保存同一批交易剪枝前后的输入？用同一tokenizer计算每笔交易的前后token数；字符数不能直接当token数。
- [ ] 分清“交易轨迹压缩比例”与“完整提示词token减少比例”；完整提示词还包含历史案例和固定指令。

### 需要的材料
最小化实现、论文算法对应版本、同一交易的原始与压缩轨迹、tokenizer名称、现有调用或token统计。

### 判断与后续处理
已有轨迹可先回答压缩规模和是否保留明显重复行为；不能据此直接证明剪枝对检测完全无损。若关键证据确实被移除且影响主要结论，再考虑保持其他配置不变、仅关闭去重的配对实验。
单条压缩日志不能支撑全数据集平均收益。没有前后记录时保留为待办，不填写估算节省率。

### 核查后应交付
前后token统计（有效样本数、均值、中位数、范围或分位数）与少量代表性轨迹对照；有额外实验时单独给性能变化。按结果修订算法说明和效率描述。

## 3. 训练集、RAG知识库和测试集分别由哪些交易组成？
对应批注：35、40。涉及数据来源、划分和420训练样本。

### 要查的东西
- [ ] 找出实际用于XGBoost训练、RAG建库、728条测试的三份清单；注明各自样本数、标签构成及来源。
- [ ] 420条训练样本从哪个总体集合选出？标签由谁/什么规则给出？是否包含另行保留的验证集？
- [ ] 随机shuffle之后如何划分，各集合的分配顺序、比例和随机种子是否有记录？
- [ ] 以链ID加交易哈希核对测试集分别与训练集、知识库的交集。明确比对的是实际运行知识库，而非仅名字相近的CSV。
- [ ] 同一攻击事件是否可能有多笔交易或多份复现记录？是否存在交易哈希不同但来自同一事件、合约或协议的情况？
- [ ] 调参数据是哪部分？是否使用过测试集指标选择参数？如有，应如实记录，不补写不存在的验证集。
- [ ] XGBoost-only与完整系统使用的XGBoost是否为同一训练过程/模型文件？若不同，各自训练和调参数据是什么？

### 需要的材料
三份运行清单、链ID/交易哈希、标签、来源事件或协议、划分脚本/种子、模型文件与知识库版本标识、已有验证集记录。

### 判断与后续处理
作者已确认测试交易与XGBoost训练及实际RAG知识库不重叠；这里是将确认落实到实际清单。不要把随机交易划分写成时间隔离、合约隔离或事件隔离。训练集与知识库是否允许彼此重叠需单独说明，不自动把它当成测试泄漏。

### 核查后应交付
样本构成表、测试与其他集合的交集统计、简短划分说明。若材料和作者确认不一致，先定位具体运行文件，不直接改论文数字。

## 3. 训练集、RAG知识库和测试集分别由哪些交易组成？
对应批注：36。涉及测试集构成及适用范围。

### 要查的东西
- [ ] 364条良性交易如何认定良性？依据交易用途、公开记录、人工检查还是其他来源？
- [ ] 分别有多少交易包含闪电贷、清算、套利、多跳交换、多合约调用？类型是否允许重叠？
- [ ] 良性与攻击交易的调用数、合约数、深度、事件数是否差异很大，以致仅靠规模即可区分？先做描述统计即可。
- [ ] 当前均衡测试集中，各类复杂良性交易的误报有多少？能否从现有预测统计，不新增推断标签？
- [ ] 是否有不均衡测试集或部署样本？若没有，避免把均衡测试的precision当作真实低攻击基率下的precision。

### 需要的材料
良性交易清单、选择/标注依据、已有轨迹、特征表、逐交易预测。

### 核查后应交付
良性样本组成与已有误报分布。只有明显缺少关键类型且需要扩展结论时，再考虑补充复杂良性样本；不要求立即重建整个数据集。

## 5. 两种提示路径各处理了多少交易，表现如何？
对应批注：39。涉及保留历史上下文与无历史上下文两种路径。

### 要查的东西
- [ ] 运行结果是否保存 `used_rag`、检索数量、XGBoost概率、最终prompt或实际调用记录？
- [ ] `used_rag`是否反映最终进入LLM的上下文，而非XGBoost筛选前的检索状态？
- [ ] 分别统计：保留历史案例；检索无合格案例；XGBoost清空案例；显式关闭RAG。原因没有记录的不要猜测。
- [ ] 每组分别统计攻击数、良性数、有效/无效输出数及TP/FP/TN/FN。
- [ ] 无历史上下文时，概率提示是否仍被传入？需区分“无案例”和“无XGBoost信息”。

### 需要的材料
同一轮实验的逐交易日志、最终提示词/消息、标签及预测。

### 判断与后续处理
不同路径处理的交易难度和类别构成可能不同，不能把分组性能差直接解释为某种提示词更好。若要比较提示模板本身，需要相同交易上的配对实验；此次可以先只统计现有路由分布。

### 核查后应交付
一张路径分布和性能表，说明统计的是最终实际输入；记录不足时列出缺失字段。

## 6. LLM结果是否重复运行过？
对应批注：41。涉及随机性及结果稳定性。

### 要查的东西
- [ ] 各实验执行了一次还是多次？失败重试与整轮独立重复要分开计数。
- [ ] 实际API模型ID、日期、temperature、top_p、seed（如支持）是什么？哪些为服务默认值？
- [ ] 同一交易有多个输出时，最后保留哪个？是否重试直到可解析，或按固定规则选择？
- [ ] 如果有多轮结果，样本集合与配置是否一致？能否统计每轮指标和逐交易标签变化？

### 需要的材料
调用设置、运行记录、重试策略、独立轮次的结果文件。

### 核查后应交付
实际运行次数和采样设置；有真实重复结果再报告均值与波动。只有一次结果就说明一次，不补造重复或置信度。对测试样本bootstrap不能替代重复调用LLM的稳定性评估。

## 7. 为什么TrxGNNBERT对应373条攻击和355条良性？
对应批注：42。涉及主比较表和基线可比性。

### 要查的东西

- [ ] 若本地重跑，确认样本哈希是否与本文728条一致；若相同，逐条比较ground-truth标签。
- [ ] 正负标签映射是否一致？是否把预测标签误用作真值，或在统计混淆矩阵时交换了FP/FN？

### 核查后应交付

## 给实验执行者的材料准备清单

建议先提供已有文件，不需要为本清单立即重跑实验：

1. 主结果与各消融对应的脚本版本、配置和结果文件名。
2. 实际训练集、知识库、测试集的交易清单和标签；如有，附划分脚本。
3. 检索原始分数、最终上下文、XGBoost概率、used_rag和最终预测记录。
4. 模型API ID、采样设置、失败重试和运行次数记录。
5. 原始/压缩轨迹及已有token统计。
6. TrxGNNBERT原始结果、旧类别检测率的分类记录。

每项核查可以标记为：已确认（附文件/位置）、发现差异（列明双方）、材料缺失、需另行实验。材料缺失不等于数据错误；现有数字不应在原因查明前被修改。
